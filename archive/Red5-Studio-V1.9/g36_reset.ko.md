# Red5 `dyn-reset` ↔ ASHRAE Guideline 36 Trim-and-Respond 대조표

> 🤖 **번역 기준선 안내**: 본 한국어 문서는 영문 원본(`g36_reset.md`)의 기계 번역 기반 기준선입니다.
> 게시 또는 외부 컨설턴트 전달 전 HVAC 분야 전문 번역가의 검토를 권장합니다.
> 표·코드·표준 인용은 원문 그대로 유지했습니다.

**대상 독자**: Red5 `dyn-reset` 노브 세트(`band_guide.md` 참조)를 이미 이해하고 있으며, 이를 ASHRAE Guideline 36 준수 운전 시퀀스(SOO)에 매핑해야 하는 HVAC 제어 엔지니어 및 시운전 담당자. 일반적으로 건물주의 인수인계 문서에서 G36을 명시한 경우 필요합니다.

**요약(TL;DR)**: `dyn-reset`은 **G36에서 영감을 받았으나** 그대로는 **G36에 완전히 준수되지 않습니다**. 본 문서는 그 격차를 메우기 위해 추가·변경·문서화해야 할 사항을 정확히 안내합니다. 제3자 시운전 담당자에게 인쇄본을 그대로 건네 점검에 활용할 수 있도록 구성되어 있습니다.

---

## 1 · 한 문단 배경

ASHRAE Guideline 36 ("High-Performance Sequences of Operation for HVAC Systems", 현행: **Guideline 36-2021**)은 30년 이상의 수요 제어 VAV 모범 사례를 단일하고 규정적인 시퀀스 라이브러리로 체계화한 표준입니다. 핵심 사상 — **모든 존을 만족시키는 가장 높은 급기 온도(SAT)와 가장 낮은 덕트 정압(SP)에서 AHU를 운전한다** — 은 Red5 `dyn-reset`이 작성된 원칙과 동일합니다. 차이점은 **카운팅 방식**에 있습니다. Red5는 각 존의 설정점 편차의 **크기(magnitude)** 에 반응하지만, G36은 존당 무시 임계값을 초과하는 존의 **개수(count)** 에 반응합니다(Trim & Respond 방식, 이하 T&R). T&R은 한 개의 비정상 존이 오작동할 때 안정성이 입증되어 있으며, G36 감사에서 검증되는 알고리즘입니다.

## 2 · 파라미터 대조표

아래는 Red5의 `dyn-reset` 노브와 G36 T&R 파라미터의 양방향 매핑입니다. 모든 노브가 G36 등가물을 갖지만, 일대일 매칭과 단서를 동반한 매칭이 혼재합니다. G36 기본값은 **Guideline 36-2021 Table 5.1.14.3** (냉방 SAT 리셋)과 **§5.1.14.4** (덕트 정압 리셋)에서 인용했습니다.

### 2.1 급기온도(SAT) 냉방 리셋

|---|---|---|---|
| `sat_min_c` | **SPmin** (최저 SAT) | 12.8 °C / 55 °F | 의미 동일. 클린룸·RH 기준 설계에서는 더 낮게 허용. |
| `sat_max_c` | **SPmax** (최고 SAT) | 18.3 °C / 65 °F | 의미 동일. 습구·제습 검토 후에만 상향. |
| `sat_init_c` | **SP0** (모드 변경 후 초기 리셋값) | SPmax (18.3 °C) | G36은 관대하게(따뜻한 SAT) 시작해서 수요에 따라 낮춥니다. Red5는 현재 `sat_init_c`로 시작; 동등성을 위해 `sat_initial_c`로 명명하고 `sat_max_c`로 설정하세요. |
| **— (Red5 등가물 없음)** | **I** (무시 요청 개수) | 2 | 응답 전 무시할 "냉방 요청" 수. **`sat_ignored_requests`로 Red5에 추가하세요.** |

> **부호 반전**에 주목: SAT는 **위로**(따뜻하게, 효율적) 트림하고 **아래로**(차갑게, 더 많은 존 만족) 응답합니다. SP는 **아래로**(낮은 압력, 적은 송풍기 전력) 트림하고 **위로**(높은 압력, 더 많은 댐퍼 개방) 응답합니다. 트림/응답 *방향*이 두 리셋 루프를 에너지 절감으로 만드는 핵심입니다.

### 2.3 외기(OA) 리셋

G36 §5.1.6은 별도의 **이코노마이저 상한**과 **최저 OA 추적**(점유 시 CO2 기반 DCV)을 요구합니다. Red5는 아직 등가물이 없으며 — 현재 OA 분율은 밴드 엔진의 엔탈피 비교에서 산출됩니다. 준수를 위해 추가해야 할 항목:

| Red5 파라미터 (추가 필요) | G36 참조 | 기본값 |
|---|---|---|
| `econ_high_limit_oat_c` | §5.1.6.2 (고정 건구온도, 기후대별) | 23.9 °C (Zone 1, 고온다습); 22.2 °C (Zone 5–8) |
| `econ_high_limit_enthalpy_kjkg` | §5.1.6.2 (고정 엔탈피, 이중 설정 옵션) | 65 kJ/kg 건공기 |
| `oa_min_cfm_per_person` | §5.1.6.3 | ASHRAE 62.1 Table 6-1 기준 (≈ 4.7 L/s/인 사무실, 7.6 L/s/인 강의실) |
| `dcv_co2_setpoint_ppm` | §5.1.6.3.b | 1000 ppm; 존 CO2 > 설정점일 때 응답 |

### 2.4 Trim & Respond 알고리즘 (의사코드)

아래 함수 하나만 추가하면 `dyn-reset`을 G36 T&R로 교체할 수 있습니다. V1.9의 `app.py`에서는 `_reset_loop` 옆에, V2.0의 `band_engine.py`에 드롭하세요.

```python
def trim_and_respond(now_setpoint, requests, params):
    """
    G36-2021 §5.1.14 Trim & Respond.

    Args:
      now_setpoint : 현재 SAT (또는 SP) 값, °C (또는 Pa)
      requests     : int — 추가 냉방을 요청하는 존의 개수
                     (SAT 루프의 경우, 냉방 루프 > 95%가 최소 2 연속 샘플
                     유지된 존을 카운트 — G36 §5.16.5 참조)
      params       : dict, 키: sp_min, sp_max, ignored, sp_trim,
                     sp_res, sp_res_max  (부호는 위 §2.1/§2.2 참조)

    Returns:
      [sp_min, sp_max] 범위로 클램프된 다음 설정점
    """
    if requests <= params['ignored']:
        # 트림: 에너지 효율적인 방향으로 되돌리기.
        proposed = now_setpoint + params['sp_trim']
    else:
        # 응답: 초과 요청마다 sp_res만큼 설정점을 끌어당김,
        # 사이클당 sp_res_max로 상한 → 한 존이 폭주해도 AHU 전체가
        # 휘둘리지 않음.
        excess = requests - params['ignored']
        delta  = params['sp_res'] * excess
        # sp_res 부호 보존하며 절대값 한도
        if abs(delta) > abs(params['sp_res_max']):
            delta = params['sp_res_max']
        proposed = now_setpoint + delta
    return max(params['sp_min'], min(params['sp_max'], proposed))
```

이 함수를 **T마다 한 번씩**(SAT는 5분, SP는 2분) VAV 폴링 루프의 최신 요청 카운트와 함께 호출하세요. `_reset_loop`의 기존 지수 감쇠를 SAT·SP 각각에 대해 이것으로 교체합니다.

### 2.5 "냉방 요청" 정의 (Red5에 새 코드가 필요한 부분)

존이 **1건의 냉방 요청**으로 카운트되는 조건: 2개의 연속 샘플(≥ 2분 간격)에서 다음 중 **하나라도** 참일 때 (G36 §5.16.5):

1. 존 온도 > 존 냉방 설정점 + 1.7 °C (3 °F) AND 존이 ≥ 2 샘플 동안 냉방 호출 중.
2. 존 공조 댐퍼 완전 개방(≥ 95%) AND 존이 여전히 냉방 설정점 + 0.6 °C (1 °F) 초과.
3. (정압 루프 한정) 존 댐퍼 > 95% 개방 AND 풍량 < 설정값의 90%.

Red5는 현재 밴드 엔진에서 존별 편차를 노출하지만, 이를 이산 요청 카운트로 집계하지 않습니다. **`int`를 반환하는 `compute_cooling_requests(zones, dt)` 함수를 추가**하고 이를 `trim_and_respond()`로 공급하세요.

## 3 · G36의 8가지 운전 모드 (Red5에 명시적으로 없는 부분)

Red5는 오늘 Givoni 밴드가 안내하는 연속 제어 체제로 운전됩니다. G36은 운전을 **이산 모드**로 분할하며 엄격한 전이 기준을 가집니다. 이 추가가 가장 큰 격차입니다.

| # | 모드 | 트리거 | 일반 설정점 |
|---|---|---|---|
| 1 | **점유(Occupied)** | 스케줄 + 임의 존이 점유 또는 온도 편차 보유 | 존 스케줄 기준 설정점 |
| 2 | **예열(Warm-up)** | OAT < 난방 설정점 − 2.8 °C AND 임의 존 < 난방 설정점 − 0.6 °C, 예정 시작 전 | 난방 전용, 외기 완전 차단, 송풍기 ON |
| 3 | **예냉(Cool-down)** | OAT > 냉방 설정점 + 2.8 °C AND 임의 존 > 냉방 설정점 + 0.6 °C, 예정 시작 전 | 냉방 전용, 외기 완전 차단, 송풍기 ON |
| 4 | **난방 셋백(Setback heating)** | 비점유 중 임의 존 < 난방 셋백(통상 15.6 °C / 60 °F) | 난방 전용, 최저 풍량 |
| 5 | **냉방 셋업(Setup cooling)** | 비점유 중 임의 존 > 냉방 셋업(통상 29.4 °C / 85 °F) | 냉방 전용, 최저 풍량 |
| 6 | **비점유(Unoccupied)** | 스케줄 비점유 AND 셋백/셋업 미트리거 | 송풍기 OFF, 댐퍼 닫힘 |
| 7 | **동결 보호(Freeze-protection)** | OAT < 1.7 °C AND 임의 존 < 4.4 °C | 4.4 °C 유지 난방, 외기 완전 차단 |
| 8 | **연기/정지(Smoke / shutdown)** | 화재 경보 입력 활성 | 송풍기 OFF (또는 화재 마샬 시퀀스), 댐퍼 닫힘 |

**전이 규칙** (G36 §5.1.4.4): 모드 진입은 **모든 트리거**가 ≥ 10분 유지된 경우에만, 이탈은 **어떤 트리거도** ≥ 10분 미충족인 경우에만. 예냉↔점유 같은 시작 시 채터링 방지를 위함.

Red5 추가 경로: 새로운 `mode_engine.py` (V2.0) / `_mode_loop` (V1.9)로 8상태 머신을 소유하고 기존 밴드 엔진의 리셋 출력을 게이팅.

## 5 · 시운전 트렌드 (CT 1–9)

G36 §6.2는 ≤ 1분 샘플 간격의 **최소 9개 30일 트렌드 로그**를 의무화합니다. 감사 시 시퀀스가 작동함을 입증하는 1차 증거입니다. Red5 V1.9 콜렉터는 대부분을 이미 로깅합니다; `collector/config.json`과 대조하세요.

| CT # | 트렌드 | 목적 |
|---|---|---|
| **CT-1** | SAT, SAT 설정점, 모든 존 온도 | SAT 리셋이 존 수요에 응답함을 확인 |
| **CT-2** | SP, SP 설정점, 모든 댐퍼 위치 | SP 리셋이 댐퍼 수요에 응답함을 확인 |
| **CT-3** | OAT, MAT, RAT, OA 댐퍼 명령 + 위치 | 이코노마이저가 엔탈피를 추적함을 확인 |
| **CT-4** | 난방 코일 밸브, 냉방 코일 밸브 | 동시 난·냉방 없음을 확인 |
| **CT-5** | 냉방·난방·정압 요청 카운트 | T&R 카운팅이 올바름을 확인 |
| **CT-6** | 운전 모드 enum | 모드 전이가 안정적임을 확인 (채터링 없음) |
| **CT-7** | 존별 풍량, 풍량 설정점, CO2 (DCV 존) | DCV가 필요 시 최저 풍량을 오버라이드함을 확인 |
| **CT-8** | 급기 송풍기 VFD 명령, 상태, 전류 | 송풍기가 명령을 추적하며 닫힌 댐퍼에 대해 작동하지 않음을 확인 |
| **CT-9** | 모든 경보 BV | 가짜 경보 없음을 확인 |

Red5 콜렉터는 이미 1분 해상도를 지원합니다. `collector/trends.json`에서 트렌드를 활성화하고 시운전 기간 30일간 연속 운영하세요.

## 6 · 경보 클래스 매트릭스 (G36 §5.1.16)

위 포인트 리스트의 모든 경보는 게시된 응답 시간과 함께 A / B / C로 분류되어야 합니다. Red5는 경보를 보유하지만 클래스 필드가 없음 — 각 경보 정의에 `alarm_class: 'A'|'B'|'C'` 추가하세요.

| 클래스 | 예시 | 알림 | 응답 시간 |
|---|---|---|---|
| **A** (생명 안전) | 동결 방지, 연기, 급기 송풍기 고장, 동결 보호 모드 활성 | 즉시 출동, 패널 가청 | < 10 분 |
| **B** (장비) | SAT/SP 편차 > 30분, 필터 부하, 밸브 오버라이드 활성, 센서 고장 | BMS 알림, 티켓 자동 생성 | < 4 시간 |
| **C** (정보) | 스케줄 오버라이드, 수동 설정점 조정, 모드 전이 | 로그만 | < 24 시간 |

## 7 · G36 준수 경로 — 격차 분석

현재 설치본에 대해 다음 체크리스트를 실행하세요:

| # | G36 요구사항 | Red5 상태 | 조치 |
|---|---|---|---|
| 1 | Trim-and-Respond SAT 리셋 | **격차** — Red5는 크기 기반 지수 감쇠 사용 | §2.4 `trim_and_respond()` 구현; `_reset_loop` SAT 브랜치 교체 |
| 2 | Trim-and-Respond SP 리셋 | **격차** — 동일 | 같은 `trim_and_respond()`를 SP 파라미터 dict로 |
| 3 | 냉방/난방/정압 요청 카운터 | **격차** — Red5는 존별 편차 보유, 집계기 없음 | §2.5에 따라 `compute_*_requests()` 추가, VAV 폴 루프에 |
| 4 | 8 운전 모드 + 전이 | **격차** — Red5는 연속 제어 | 새 `mode_engine.py` (V2.0) / `_mode_loop` (V1.9); 위 §3 |
| 5 | 고정 건구온도 또는 엔탈피 상한 이코노마이저 | **부분** — Red5는 엔탈피 비교 사용; 명시적 상한 필요 | §2.3에 따라 `econ_high_limit_oat_c`, `econ_high_limit_enthalpy_kjkg` 추가 |
| 6 | ASHRAE 62.1 기준 최저 OA / DCV | **격차** — Red5는 OA 분율 보유, 인당 최저 추적 없음 | VAV 폴에 CO2 입력 + DCV 오버라이드 로직 추가 |
| 7 | AHU당 40개 필수 포인트 | **대부분 OK** — Red5 V1.9는 ~35개를 BACnet으로 노출 | §4.1과 `bacnet_map.json` 대조; 누락 ~5개 추가 (대부분 계산 AV 요청 카운트) |
| 8 | VAV당 20개 필수 포인트 | **대부분 OK** — 동일 | 점검; 요청 플래그 BV 추가 |
| 9 | 9개 시운전 트렌드 @ 1분 | **OK** — Red5 콜렉터 이미 지원 | `collector/trends.json`에서 활성화; 30일 운영 |
| 10 | 경보 클래스 A/B/C 태깅 | **격차** — Red5 경보 존재, 미분류 | §6에 따라 `alarm_class` 필드 추가 |
| 11 | 동결 보호 자동 모드 | **부분** — 동결 방지 입력 배선됨, 모드 강제 안 함 | #4에서 추가하는 모드 엔진에 연결 |
| 12 | 동시 난·냉방 없음 | **OK** — Red5 밴드 엔진이 방지 | CT-4 트렌드로 검증 |

**12개 격차 모두 해소 추정 노력**: V2.0의 경우 약 3–4 개발-주, 더하여 대표 계절 동안 CT 트렌드 수집 1주. V1.9의 경우 BACnet 포인트 확장에 약 2주 추가 (새 포인트마다 컨트롤러 플래시 필요).

## 8 · "그냥 스펙 시트에 G36이라고 *적기만* 하면 되는 경우"

목표가 마케팅 동등성(실제 G36 준수 아님)이라면 최소 신뢰성 있는 구현:

1. **§2.4 trim_and_respond()** — 감쇠 기반 리셋 교체 (≈ 1일).
2. **§2.5 냉방 요청 카운터** — 존별 집계 (≈ 1일).
3. **§3 모드 엔진** — 4-모드 부분집합(점유 / 비점유 / 예열 / 예냉)도 감사 점검의 90%를 커버 (≈ 3일).
4. **§5 CT-1, CT-2, CT-5** — 3개 트렌드, 각 30일 (개발 작업 0; 활성화만).
5. **§7 7행** — BACnet 포인트 리스트 확인.

약 1 개발-주 분량이며 **"G36 인지(G36-aware)"** 상태에 도달 — 일반 스펙은 충족하나 ASHRAE 감사는 통과 못함. 건물주가 제3자 시운전 담당자(예: Engineering Economics, kW Engineering, P2S 같은 회사의 CxA)를 보낸다면 **반드시** §3–§7 전체 체크리스트를 실행하며 부분 구현은 지적됩니다.
