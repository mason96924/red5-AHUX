# <!--FROZEN-->HVAC<!--/FROZEN--> Control Algorithms — <!--FROZEN-->AHU<!--/FROZEN--> & <!--FROZEN-->VAV<!--/FROZEN-->
## Demand-Driven Control Based on Givoni Comfort Zone
## No Temperature Setpoints — Comfort Zone <!--FROZEN-->IS<!--/FROZEN--> the Setpoint

---

## 1. <!--FROZEN-->PHILOSOPHY<!--/FROZEN-->

### No Setpoints. Only Physics and Boundaries.

Traditional <!--FROZEN-->HVAC<!--/FROZEN--> uses fixed temperature setpoints (e.g., "maintain 22°C").
This system uses <!--FROZEN-->NONE<!--/FROZEN-->. Instead:

- The **Givoni Comfort Zone** is the hard boundary (20-27°C <!--FROZEN-->DB<!--/FROZEN-->, 20-80% <!--FROZEN-->RH<!--/FROZEN-->).
- The **only operator setpoint** is humidity (based on health data and occupant preference).
- Temperature self-regulates through the <!--FROZEN-->SA<!--/FROZEN--> ↔ <!--FROZEN-->VAV<!--/FROZEN--> zone dynamic.
- **Cold weather**: <!--FROZEN-->OA<!--/FROZEN--> < zone → heating process → <!--FROZEN-->SA<!--/FROZEN--> warmer than <!--FROZEN-->OA<!--/FROZEN--> → <!--FROZEN-->VAV<!--/FROZEN--> zone drifts toward <!--FROZEN-->SA<!--/FROZEN--> → naturally approaches ~20°C <!--FROZEN-->DB<!--/FROZEN-->.
- **Hot weather**: <!--FROZEN-->OA<!--/FROZEN--> > zone → cooling process → <!--FROZEN-->SA<!--/FROZEN--> cooler than <!--FROZEN-->OA<!--/FROZEN--> → <!--FROZEN-->VAV<!--/FROZEN--> zone drifts toward <!--FROZEN-->SA<!--/FROZEN--> → naturally approaches ~27°C <!--FROZEN-->DB<!--/FROZEN-->.

### The Demand Signal

The control demand is NOT "how far from a setpoint" but rather:
- **If <!--FROZEN-->VAV<!--/FROZEN--> zone point is <!--FROZEN-->OUTSIDE<!--/FROZEN--> the comfort zone**: Demand = ΔH between the zone point and the nearest <!--FROZEN-->CZ<!--/FROZEN--> boundary.
- **If <!--FROZEN-->VAV<!--/FROZEN--> zone point is <!--FROZEN-->INSIDE<!--/FROZEN--> the comfort zone**: Demand = 0. No heating or cooling demand.

The system only acts when zones drift outside (or threaten to drift outside) the comfort zone.

## 2. <!--FROZEN-->GIVONI<!--/FROZEN--> <!--FROZEN-->COMFORT<!--/FROZEN--> <!--FROZEN-->ZONE<!--/FROZEN--> <!--FROZEN-->DEFINITION<!--/FROZEN-->

```
CZ Boundaries:
  Temperature: 20.0°C to 27.0°C dry-bulb
  Humidity:    20% RH to 80% RH
  Corner taper: At 27°C, RH caps at 50% (upper-right boundary)

Hard Rules:
  - VAV zone temp MUST NOT fall below 20°C DB
  - VAV zone temp MUST NOT rise above 27°C DB  
  - VAV zone RH MUST stay between 20% and 80%
  - Zone point must remain INSIDE the CZ polygon at all times
```

## 3. <!--FROZEN-->DEMAND<!--/FROZEN--> <!--FROZEN-->CALCULATION<!--/FROZEN-->

### 3.1 <!--FROZEN-->VAV<!--/FROZEN--> Zone Demand

```
ZONE_W = humidity_ratio(ZONE_TEMP, ZONE_RH)
IN_CZ = point_in_polygon(ZONE_TEMP, ZONE_W, GIVONI_CZ_VERTICES)

IF IN_CZ:
    HEATING_DEMAND = 0
    COOLING_DEMAND = 0
    
ELSE:
    // Find the nearest CZ boundary point
    // Project zone point onto CZ polygon edge
    
    IF ZONE_TEMP < 20.0:
        // Below CZ — heating demand
        BOUNDARY_TEMP = 20.0
        BOUNDARY_W = constrain_humidity(ZONE_W, BOUNDARY_TEMP)
        HEATING_DEMAND = enthalpy(BOUNDARY_TEMP, BOUNDARY_W) - enthalpy(ZONE_TEMP, ZONE_W)
        COOLING_DEMAND = 0
        
    ELSE IF ZONE_TEMP > 27.0:
        // Above CZ — cooling demand
        BOUNDARY_TEMP = 27.0
        BOUNDARY_W = constrain_humidity(ZONE_W, BOUNDARY_TEMP)
        COOLING_DEMAND = enthalpy(ZONE_TEMP, ZONE_W) - enthalpy(BOUNDARY_TEMP, BOUNDARY_W)
        HEATING_DEMAND = 0
        
    ELSE IF ZONE_RH > 80.0:
        // Temp in range but too humid — dehumidification demand
        BOUNDARY_W = humidity_ratio(ZONE_TEMP, 80.0)
        COOLING_DEMAND = enthalpy(ZONE_TEMP, ZONE_W) - enthalpy(ZONE_TEMP, BOUNDARY_W)
        HEATING_DEMAND = 0
        
    ELSE IF ZONE_RH < 20.0:
        // Temp in range but too dry — humidification demand (not heating/cooling)
        HUMIDIFICATION_DEMAND = humidity_ratio(ZONE_TEMP, 20.0) - ZONE_W
        HEATING_DEMAND = 0
        COOLING_DEMAND = 0

// constrain_humidity(W, T): clamp W to be within 20-80% RH at temperature T
```

### 3.2 Aggregate <!--FROZEN-->AHU<!--/FROZEN--> Demand

```
ALL_HEATING_DEMANDS[] = [each VAV's HEATING_DEMAND]
ALL_COOLING_DEMANDS[] = [each VAV's COOLING_DEMAND]

TOTAL_HEATING_DEMAND = sum(ALL_HEATING_DEMANDS)
TOTAL_COOLING_DEMAND = sum(ALL_COOLING_DEMANDS)
MAX_HEATING_DEMAND   = max(ALL_HEATING_DEMANDS)
MAX_COOLING_DEMAND   = max(ALL_COOLING_DEMANDS)
ZONES_OUTSIDE_CZ     = count where demand > 0
```

## 4. <!--FROZEN-->AHU<!--/FROZEN--> <!--FROZEN-->CONTROL<!--/FROZEN--> <!--FROZEN-->ALGORITHM<!--/FROZEN-->

### 4.1 Inputs
```
OA_TEMP, OA_RH       = Outside Air conditions
RA_TEMP, RA_RH       = Return Air conditions
SA_TEMP, SA_RH       = Supply Air conditions [measured feedback]
SA_STATIC_PRESSURE    = Duct static pressure [measured]
HUMIDITY_SETPOINT     = Operator-set target humidity (% RH)
ALL_VAV_DEMANDS[]     = Demand signals from all VAV zones
ALL_VAV_DAMPERS[]     = Current damper positions from all VAVs
```

### 4.2 Outputs
```
OA_DAMPER    = Outside Air damper (0-100%)
HC_VALVE     = Heating Coil valve (0-100%)
CC_VALVE     = Cooling Coil valve (0-100%)
HUM_VALVE    = Humidification valve (0-100%)
FAN_SPEED    = Supply Fan speed (0-100%)
```

### 4.3 The Core Logic: React to Demand, Not Setpoints

```
// AHU does not chase a temperature setpoint.
// It reacts to the aggregate demand from all VAV zones.

IF TOTAL_HEATING_DEMAND > 0 AND TOTAL_COOLING_DEMAND == 0:
    // ---- HEATING PROCESS ----
    // OA is cold. Zones are drifting below 20°C.
    // Heat SA so VAV zones are pulled back into CZ.
    
    // OA/RA mixing — minimize OA in cold weather
    IF OA_TEMP < 5.0:
        OA_DAMPER = MIN_OA_POS                    // Freeze protection
    ELSE:
        // Mix just enough OA for ventilation
        OA_DAMPER = MIN_OA_POS
    
    // Heating coil — proportional to worst zone's demand
    HC_OUTPUT = MAX_HEATING_DEMAND * HEATING_GAIN  // Scale demand to valve %
    HC_VALVE = clamp(HC_OUTPUT, 0, 100)
    CC_VALVE = 0
    
ELSE IF TOTAL_COOLING_DEMAND > 0 AND TOTAL_HEATING_DEMAND == 0:
    // ---- COOLING PROCESS ----
    // OA is hot. Zones are drifting above 27°C.
    // Cool SA so VAV zones are pulled back into CZ.
    
    // Economizer first — free cooling if OA is favorable
    OA_H = enthalpy(OA_TEMP, humidity_ratio(OA_TEMP, OA_RH))
    RA_H = enthalpy(RA_TEMP, humidity_ratio(RA_TEMP, RA_RH))
    
    IF OA_H < RA_H:
        // Free cooling available — increase OA
        OA_DAMPER = map(RA_H - OA_H, 0, 15, MIN_OA_POS, 100)
    ELSE:
        OA_DAMPER = MIN_OA_POS
    
    // Cooling coil — proportional to worst zone's demand
    CC_OUTPUT = MAX_COOLING_DEMAND * COOLING_GAIN
    CC_VALVE = clamp(CC_OUTPUT, 0, 100)
    HC_VALVE = 0

ELSE IF TOTAL_HEATING_DEMAND == 0 AND TOTAL_COOLING_DEMAND == 0:
    // ---- ALL ZONES IN COMFORT ZONE ----
    // No thermal demand. Maintain minimum operation.
    OA_DAMPER = MIN_OA_POS
    HC_VALVE = 0
    CC_VALVE = 0
    // Fan at minimum for ventilation
    
ELSE:
    // ---- MIXED DEMAND (some zones hot, some cold) ----
    // Prioritize the larger demand
    IF TOTAL_COOLING_DEMAND > TOTAL_HEATING_DEMAND:
        CC_VALVE = clamp(MAX_COOLING_DEMAND * COOLING_GAIN, 0, 100)
        HC_VALVE = 0
    ELSE:
        HC_VALVE = clamp(MAX_HEATING_DEMAND * HEATING_GAIN, 0, 100)
        CC_VALVE = 0
    // Note: VAVs with reheat handle the opposite-demand zones individually

// HEATING_GAIN, COOLING_GAIN: tuning constants that convert kJ/kg demand 
// into valve %. Start with 10.0 (i.e., 1 kJ/kg demand = 10% valve).
// Tune based on coil capacity.
```

### 4.4 Humidity Control (The Only Setpoint)

```
// HUMIDITY_SETPOINT is the ONLY operator-controlled setpoint.
// Set by building operator based on:
//   - Occupant health (40-60% RH recommended by WHO/ASHRAE)
//   - Occupant preference
//   - Seasonal health data (higher in dry winter, lower in humid summer)

SA_RH_ERROR = HUMIDITY_SETPOINT - SA_RH

IF SA_RH_ERROR > 2.0:
    // Too dry — humidify
    HUM_VALVE = PID(SA_RH_ERROR, Kp=2.0, Ki=0.3, Kd=0.1)
    HUM_VALVE = clamp(HUM_VALVE, 0, 100)
ELSE IF SA_RH_ERROR < -5.0:
    // Too humid — increase cooling coil slightly for dehumidification
    CC_VALVE = max(CC_VALVE, abs(SA_RH_ERROR) * 1.5)
    CC_VALVE = clamp(CC_VALVE, 0, 100)
    HUM_VALVE = 0
ELSE:
    HUM_VALVE = 0
```

### 4.5 Fan Speed / Static Pressure

```
// Static pressure control remains the same — demand-responsive
SP_ERROR = SA_SP_SETPOINT - SA_STATIC_PRESSURE
FAN_SPEED = PID(SP_ERROR, Kp=3.0, Ki=0.8, Kd=0.1)
FAN_SPEED = clamp(FAN_SPEED, MIN_FAN, 100)

// Static Pressure Reset — based on VAV damper positions
MAX_DAMPER = max(ALL_VAV_DAMPERS)
IF MAX_DAMPER < 70:
    SA_SP_SETPOINT -= 5 Pa per cycle    // Over-pressurized
ELSE IF MAX_DAMPER > 95:
    SA_SP_SETPOINT += 10 Pa per cycle   // Starving zones
```

## 5. <!--FROZEN-->VAV<!--/FROZEN--> <!--FROZEN-->CONTROL<!--/FROZEN--> <!--FROZEN-->ALGORITHM<!--/FROZEN-->

### 5.1 The Principle

The <!--FROZEN-->VAV<!--/FROZEN--> does NOT chase a temperature setpoint.
It modulates airflow to keep the zone point inside the <!--FROZEN-->CZ<!--/FROZEN-->
while minimizing its psychrometric distance to <!--FROZEN-->SA<!--/FROZEN-->.

The zone temperature naturally gravitates:
- Toward ~20°C when <!--FROZEN-->SA<!--/FROZEN--> is heated (cold weather)
- Toward ~27°C when <!--FROZEN-->SA<!--/FROZEN--> is cooled (hot weather)

### 5.2 <!--FROZEN-->VAV<!--/FROZEN--> <!--FROZEN-->WITHOUT<!--/FROZEN--> Reheat

```
ZONE_W = humidity_ratio(ZONE_TEMP, ZONE_RH)
IN_CZ = point_in_polygon(ZONE_TEMP, ZONE_W, CZ_VERTICES)

// Distance from zone point to SA point (psychrometric)
DIST_SA = psych_distance(ZONE_TEMP, ZONE_W, SA_TEMP, SA_W)

IF NOT IN_CZ:
    // ZONE IS OUTSIDE COMFORT ZONE — ACT
    
    IF ZONE_TEMP < 20.0:
        // Too cold — open damper to receive more warm SA air
        DEMAND = 20.0 - ZONE_TEMP
        DAMPER_POS = map(DEMAND, 0, 5, MIN_DAMPER, 100)
        
    ELSE IF ZONE_TEMP > 27.0:
        // Too hot — open damper to receive more cool SA air
        DEMAND = ZONE_TEMP - 27.0
        DAMPER_POS = map(DEMAND, 0, 5, MIN_DAMPER, 100)
        
    ELSE:
        // Temperature OK but humidity out of range
        // Modulate damper moderately to exchange air
        DAMPER_POS = 50

ELSE:
    // ZONE IS INSIDE COMFORT ZONE — MINIMIZE ENERGY
    
    // Drift damper toward minimum while zone stays in CZ
    // The closer to SA point, the less airflow needed to maintain position
    
    IF DIST_SA < 2.0:
        // Very close to SA — minimal airflow needed
        DAMPER_POS = MIN_DAMPER
    ELSE IF DIST_SA < 5.0:
        // Moderate distance — proportional airflow
        DAMPER_POS = map(DIST_SA, 2, 5, MIN_DAMPER, 50)
    ELSE:
        // Far from SA — more airflow to maintain position
        DAMPER_POS = map(DIST_SA, 5, 12, 50, 80)
    
    // Boundary proximity guard: if near CZ edge, increase airflow
    IF ZONE_TEMP < 21.0 AND SA_TEMP > ZONE_TEMP:
        DAMPER_POS = max(DAMPER_POS, 40)   // Prevent falling below 20
    IF ZONE_TEMP > 26.0 AND SA_TEMP < ZONE_TEMP:
        DAMPER_POS = max(DAMPER_POS, 40)   // Prevent rising above 27

DAMPER_POS = clamp(DAMPER_POS, MIN_DAMPER, 100)
```

### 5.3 <!--FROZEN-->VAV<!--/FROZEN--> <!--FROZEN-->WITH<!--/FROZEN--> Reheat

```
// Same as above, PLUS reheat for the cold-weather edge case:
// When AHU is in cooling mode (serving majority of zones)
// but THIS zone is below 20°C.

IF NOT IN_CZ AND ZONE_TEMP < 20.0:
    // Zone is cold but AHU is cooling (can't help this zone)
    DAMPER_POS = MIN_DAMPER           // Minimize cold SA intake
    REHEAT_DEMAND = 20.0 - ZONE_TEMP
    REHEAT_VALVE = PID(REHEAT_DEMAND, Kp=5.0, Ki=0.5, Kd=0.2)
    REHEAT_VALVE = clamp(REHEAT_VALVE, 0, 100)

ELSE IF IN_CZ AND ZONE_TEMP < 21.0 AND SA_TEMP < ZONE_TEMP:
    // In CZ but dangerously close to lower boundary,
    // and SA is colder (would push zone out)
    DAMPER_POS = MIN_DAMPER
    REHEAT_VALVE = map(21.0 - ZONE_TEMP, 0, 1, 0, 30)  // Gentle reheat

ELSE:
    REHEAT_VALVE = 0
    // Normal damper logic from 5.2 applies
```

## 8. <!--FROZEN-->HELPER<!--/FROZEN--> <!--FROZEN-->FUNCTIONS<!--/FROZEN-->

### Psychrometric Distance (<!--FROZEN-->SA<!--/FROZEN-->-to-<!--FROZEN-->VAV<!--/FROZEN--> Proximity)

This is the key metric for how efficiently the <!--FROZEN-->AHU<!--/FROZEN--> is serving each <!--FROZEN-->VAV<!--/FROZEN--> zone.
It measures the Euclidean distance between two points on the psychrometric chart
(e.g., <!--FROZEN-->SA<!--/FROZEN--> point and <!--FROZEN-->VAV<!--/FROZEN--> zone point), with humidity ratio scaled to comparable units.

```
psych_distance(T1, W1, T2, W2):
    dT = T1 - T2                       // °C difference
    dW = (W1 - W2) * 1000              // kg/kg → g/kg (scaling factor)
    return sqrt(dT² + dW²)

// Why scale W by 1000?
// Temperature is in °C (range ~10-35), W is in kg/kg (range ~0.005-0.020).
// Without scaling, humidity is negligible. Converting to g/kg (5-20) makes
// both axes comparable in magnitude.
//
// Example:
//   VAV zone: 24.0°C, W=0.0120 kg/kg (12.0 g/kg)
//   SA point: 14.0°C, W=0.0085 kg/kg (8.5 g/kg)
//   dT = 10.0, dW = 3.5 g/kg
//   Distance = sqrt(100 + 12.25) = 10.6
//
// Dashboard color coding:
//   Green  (< 3):  Very close — efficient, minimal energy transfer
//   Grey   (3-6):  Moderate distance
//   Amber  (> 6):  Large energy gap between supply and zone
```

### Other Helpers

```
// Psychrometric distance (normalized T/W space)
psych_distance(T1, W1, T2, W2):
    dT = T1 - T2
    dW = (W1 - W2) * 1000    // kg/kg → g/kg for comparable scale
    return sqrt(dT² + dW²)

// Enthalpy (kJ/kg dry air)
enthalpy(T, W):
    return 1.006 * T + W * (2501 + 1.86 * T)

// Humidity ratio (kg water / kg dry air)
humidity_ratio(T, RH):
    Psat = saturation_pressure(T)
    Pw = (RH / 100) * Psat
    return 0.621945 * Pw / (101.325 - Pw)

// Constrain humidity ratio to CZ RH limits at given temperature
constrain_W(W, T):
    W_low  = humidity_ratio(T, 20)
    W_high = humidity_ratio(T, 80)
    return clamp(W, W_low, W_high)

// Map value from one range to another
map(value, in_min, in_max, out_min, out_max):
    return out_min + (value - in_min) * (out_max - out_min) / (in_max - in_min)

// PID controller
PID(error, Kp, Ki, Kd):
    integral += error * dt
    integral = clamp(integral, -LIMIT, LIMIT)
    derivative = (error - prev_error) / dt
    prev_error = error
    return Kp * error + Ki * integral + Kd * derivative
```

## 9. <!--FROZEN-->ANIMATION<!--/FROZEN--> <!--FROZEN-->CONTROL<!--/FROZEN--> <!--FROZEN-->MODES<!--/FROZEN--> (<!--FROZEN-->V1<!--/FROZEN-->.7 — Simulation Foundation)

The psychrometric dynamics animation implements 3 selectable modes via <!--FROZEN-->UI<!--/FROZEN--> buttons.
These modes serve as the visual proof-of-concept for the control algorithm and will
be the basis for the real controller implementation.

### 9.1 Shared Constants & Constraints

```
CZ Temperature:   CZ_T_LO = 20°C,  CZ_T_HI = 27°C
SA Temperature:   SA_T_LO = 18.5°C (= CZ_T_LO - max_min_heatGain)
                  SA_T_HI = 23.5°C (= CZ_T_HI - max_max_heatGain)

CZ Humidity:      DYNAMIC — derived from 40-60% RH at zone temperature
                  CZ_W_LO = getW(T_sp, 40% RH)
                  CZ_W_HI = getW(T_sp, 60% RH)
SA Humidity:      SA_W_LO = CZ_W_LO - 0.0006  (offset by min moisture gain)
                  SA_W_HI = CZ_W_HI - 0.001   (offset by max moisture gain)

VAV Heat Gains:   heatGain[i] = 2.5 + (i - 2.5) * 0.4   → range 1.5..3.5°C
VAV Moist Gains:  moistGain[i] = 0.0008 + (i - 2.5) * 0.0001  → range 0.0006..0.001 kg/kg

Zone Avg Target:  T_sp = clamp(OA.t, 21, 26)
                  (Accounts for ±1°C VAV spread around average)

OA Mixing Factor: 12% (SA = 88% PI_command + 12% OA)
```

### 9.2 Design Principle — Minimum Delta-H

In <!--FROZEN-->ALL<!--/FROZEN--> modes, the system targets the Comfort Zone boundary closest to <!--FROZEN-->OA<!--/FROZEN--> conditions.
This minimizes the enthalpy difference (deltaH) between Supply Air and Outside Air,
which directly translates to minimum energy expenditure.

```
Winter (OA = 2°C, 2.8 g/kg):
  → T_sp = 21°C (low end of CZ)
  → W target from 40% RH at 21°C ≈ 6.2 g/kg (low end of humidity CZ)
  → VAVs cluster at bottom-left of CZ → minimum deltaH from cold/dry OA

Summer (OA = 36°C, 20 g/kg):
  → T_sp = 26°C (high end of CZ)
  → W target from 60% RH at 26°C ≈ 12.7 g/kg (high end of humidity CZ)
  → VAVs cluster at top-right of CZ → minimum deltaH from hot/humid OA

Spring (OA = 20°C, 8.8 g/kg):
  → T_sp = 21°C, W ≈ OA.w (near economizer, minimal processing)
```

### 9.3 <!--FROZEN-->MODE<!--/FROZEN--> 1: <!--FROZEN-->SEASONAL<!--/FROZEN--> (No Setpoint — Pure Nature)

**Purpose**: Illustrates what nature does with <!--FROZEN-->NO<!--/FROZEN--> humidity control and <!--FROZEN-->NO<!--/FROZEN--> setpoints.
<!--FROZEN-->AHU<!--/FROZEN--> heats/cools to keep VAVs in <!--FROZEN-->CZ<!--/FROZEN--> temperature range, but humidity is whatever
the outdoor air delivers. No humidification, no dehumidification.

This demonstrates the **cost of not controlling moisture** — in winter, VAVs will
be very dry; in summer, very humid. Both conditions are uncomfortable and unhealthy.

```
Algorithm:
  SA_t_cmd = clamp(OA.t, SA_T_LO, SA_T_HI)         // temp: keep in CZ range
  SA_w_cmd = clamp(OA.w, 0.001, getW(SA_t_cmd, 98)) // humidity: FREE, follows OA

  SA.t moves toward SA_t_cmd with lag 0.04 + noise
  SA.w moves toward SA_w_cmd with lag 0.04 + noise

Behavior:
  - Winter (OA 2°C, 2.8 g/kg): SA ≈ 18.5°C / 2.8 g/kg → VAVs very dry (~18% RH)
  - Summer (OA 36°C, 20 g/kg): SA ≈ 23.5°C / 20 g/kg → VAVs very humid (>80% RH)
  - Spring/Autumn: Near-comfortable (OA already moderate)

Constraints:
  - Temperature: SA bounded to [18.5, 23.5]°C (CZ-derived)
  - Humidity: NO constraint — physical saturation limit only
  - No PI controller, no setpoint panel, no controller state badge
```

### 9.4 <!--FROZEN-->MODE<!--/FROZEN--> 2: W <!--FROZEN-->SETPOINT<!--/FROZEN--> (Air Conditioning — Heating/Cooling Only)

**Purpose**: Simulates conventional air conditioning <!--FROZEN-->WITHOUT<!--/FROZEN--> humidification or
dehumidification. Only heating and cooling are applied. The W setpoint represents
maintaining a constant moisture ratio through sensible heat processes (horizontal
movement on the psychrometric chart).

No moisture is added or removed — the air's absolute humidity (W) stays at the
setpoint value. Heating raises T (<!--FROZEN-->RH<!--/FROZEN--> drops). Cooling lowers T (<!--FROZEN-->RH<!--/FROZEN--> rises, until
dew point is reached).

```
User Input:
  W_sp = slider value (3..20 g/kg, default 8.0 g/kg)

Algorithm:
  err_w = W_sp - avgW        // zone avg humidity error
  err_t = T_sp - avgT        // zone avg temperature error (T_sp is dynamic)

  integral_w += err_w * dt   (clamped to ±0.008)
  integral_t += err_t * dt   (clamped to ±12)

  SA_w_cmd = W_sp + Kp_w * err_w + Ki_w * integral_w
  SA_t_cmd = T_sp + Kp_t * err_t + Ki_t * integral_t

  SA_w_cmd = clamp(SA_w_cmd, 0.001, 0.025)       // physical limits only
  SA_t_cmd = clamp(SA_t_cmd, SA_T_LO, SA_T_HI)   // CZ-derived T bounds
  SA_w_cmd = min(SA_w_cmd, getW(SA_t_cmd, 98%))   // saturation limit

  // OA mixing (12%):
  mixT = SA_t_cmd * 0.88 + OA.t * 0.12
  mixW = SA_w_cmd * 0.88 + OA.w * 0.12

  SA.t moves toward mixT with lag 0.05 + noise
  SA.w moves toward mixW with lag 0.05 + noise

  // Final physical clamp (no CZ humidity restriction)
  SA.t = clamp(SA.t, SA_T_LO, SA_T_HI)
  SA.w = clamp(SA.w, 0.001, getW(SA.t, 98%))

PI Gains:
  Kp_w = 3.5,  Ki_w = 0.8   (humidity)
  Kp_t = 2.5,  Ki_t = 0.6   (temperature)

Key Design Decision:
  NO CZ humidity clamp on SA in this mode. The user's W setpoint overrides
  the 40-60% RH comfort bounds. The PI must be free to drive SA to whatever
  humidity is needed to converge on W_sp. If the user sets W_sp = 3 g/kg,
  the system will deliver 3 g/kg even though that's below 40% RH.

Convergence:
  At steady state: avgW ≈ W_sp, err_w ≈ 0
  SA.w ≈ W_sp - avgMoistGain + integral_offset_from_OA_mixing
  The integral compensates for the OA mixing disturbance automatically.

Controller State Detection:
  heating      = SA.t > OA.t + 2
  cooling      = SA.t < OA.t - 2
  humidifying  = SA.w > OA.w + 0.001
  dehumidifying = SA.w < OA.w - 0.001
  economizer   = |SA.t - OA.t| < 3 AND |SA.w - OA.w| < 0.002
  → Display: HEAT+HUMID, COOL+DEHUMID, ECONOMIZER, etc.
```

### 9.5 <!--FROZEN-->MODE<!--/FROZEN--> 3: <!--FROZEN-->RH<!--/FROZEN--> <!--FROZEN-->SETPOINT<!--/FROZEN--> (Full Air Conditioning — Ideal Control)

**Purpose**: Full <!--FROZEN-->HVAC<!--/FROZEN--> with active humidification AND dehumidification. This is
the ideal way to control indoor air quality. The system actively adds moisture
(humidifier) or removes it (cooling below dew point + reheat) to maintain the
operator's <!--FROZEN-->RH<!--/FROZEN--> setpoint.

```
User Input:
  RH_sp = slider value (20..80 %RH, default 50%)

Algorithm:
  err_rh = RH_sp - avgRH     // zone avg RH error
  err_t  = T_sp - avgT       // zone avg temperature error

  integral_rh += err_rh * dt  (clamped to ±30)
  integral_t  += err_t * dt   (clamped to ±12)

  SA_rh_cmd = RH_sp + Kp_rh * err_rh + Ki_rh * integral_rh
  SA_t_cmd  = T_sp + Kp_t * err_t + Ki_t * integral_t

  SA_rh_cmd = clamp(SA_rh_cmd, 5, 98)
  SA_t_cmd  = clamp(SA_t_cmd, SA_T_LO, SA_T_HI)

  SA_w_cmd = getW(SA_t_cmd, SA_rh_cmd)   // convert RH command to W at SA temp
  SA_w_cmd = clamp(SA_w_cmd, 0.001, 0.025)

  // OA mixing (12%):
  mixT = SA_t_cmd * 0.88 + OA.t * 0.12
  mixW = SA_w_cmd * 0.88 + OA.w * 0.12

  SA.t moves toward mixT with lag 0.05 + noise
  SA.w moves toward mixW with lag 0.05 + noise

  SA.t = clamp(SA.t, SA_T_LO, SA_T_HI)
  SA.w = clamp(SA.w, 0.001, getW(SA.t, 98%))

PI Gains:
  Kp_rh = 1.5,  Ki_rh = 0.3   (relative humidity)
  Kp_t  = 2.5,  Ki_t  = 0.6   (temperature)

Key Design Decision:
  Same as W mode — NO CZ humidity clamp. The user's RH setpoint overrides
  the 40-60% comfort bounds. The PI converts the RH command into an equivalent
  W command using inverse psychrometrics at SA temperature.

RH vs W — Why Both Modes?
  - W setpoint: Controls absolute moisture content. Useful when the process
    requires a specific moisture load (e.g., data centers, clean rooms).
  - RH setpoint: Controls perceived humidity. Useful for occupant comfort
    since RH is what humans feel. Same W at different temperatures gives
    different RH — this mode accounts for that coupling.
```

## 10. <!--FROZEN-->OA<!--/FROZEN-->-<!--FROZEN-->BAND<!--/FROZEN--> <!--FROZEN-->SUPERVISORY<!--/FROZEN--> <!--FROZEN-->SETPOINT<!--/FROZEN--> <!--FROZEN-->SCHEDULER<!--/FROZEN--> (<!--FROZEN-->V2<!--/FROZEN-->.0)

### 10.1 Architecture — Two-Layer Control

The system operates in two layers. This section defines **Layer 1** — the supervisory
scheduler that classifies outdoor air conditions into one of 10 bands and outputs
<!--FROZEN-->SA<!--/FROZEN--> setpoints. The existing <!--FROZEN-->PI<!--/FROZEN--> controller (Sections 4-5) is **Layer 2** — it tracks
those setpoints by modulating physical actuators.

```
                  ┌──────────────────────────────────────────────┐
                  │              OUTDOOR AIR SENSORS              │
                  │           OA_T, OA_RH → compute OA_W, OA_H   │
                  └────────────────────┬─────────────────────────┘
                                       │
                            ┌──────────▼──────────┐
                            │   LAYER 1 (THIS)    │
                            │   OA Band Classifier │
                            │                     │
                            │  10-Band Lookup →    │
                            │  SA_T_SP             │
                            │  SA_W_SP (or SA_RH)  │
                            │  OA_DAMPER_SP        │
                            │  HUM_MODE            │
                            │  CONTROL_MODE_TAG    │
                            └──────────┬──────────┘
                                       │ setpoints
                            ┌──────────▼──────────┐
                            │   LAYER 2 (Sec 4)   │
                            │   PI Tracking Loop   │
                            │                     │
                            │  HC_VALVE ← PI(T)   │
                            │  CC_VALVE ← PI(T,W) │
                            │  HUM_VALVE ← PI(W)  │
                            │  OA_DAMPER ← direct  │
                            │  FAN_SPEED ← PI(SP)  │
                            └──────────┬──────────┘
                                       │ actuator commands
                            ┌──────────▼──────────┐
                            │     PHYSICAL AHU     │
                            │  HCV, Hydration,     │
                            │  OA Damper, SA Fan,   │
                            │  Flow, DP Sensor      │
                            └─────────────────────┘
```

### 10.2 Physical Plant Constraints

```
Available Actuators:
  HCV_HEAT       Heating coil valve (0-100%)
  HCV_COOL       Cooling coil valve (0-100%)
  HUM_VALVE      Hydration valve / humidifier (0-100%)
  OA_DAMPER      Outside air damper (0-100%)
  SA_FAN         Supply air fan VFD (0-100%)

Sensors Available:
  OA_T, OA_RH    Outside air
  SA_T, SA_RH    Supply air (discharge)
  RA_T, RA_RH    Return air
  DAMPER_POS     Damper feedback
  VALVE_POS_H    Heating valve feedback
  VALVE_POS_C    Cooling valve feedback
  DP             Duct differential pressure
  FLOW           Airflow rate

CRITICAL CONSTRAINT — NO DEHUMIDIFIER:
  This plant has NO dedicated dehumidification device (no desiccant wheel,
  no enthalpy wheel, no run-around coil). The ONLY way to remove moisture is:

  1. CC SUBCOOL — Cool air below its dew point on the cooling coil. Moisture
     condenses on the coil fins. The leaving air is cold and dehumidified.
     Then HC REHEAT to bring SA_T back up to target. This is energy-intensive
     but effective. Uses both HCV_COOL and HCV_HEAT simultaneously.

  2. OA REDUCTION — Close OA damper to minimum. Recirculate drier return air.
     Effective when RA is significantly drier than OA. Limited by ventilation
     code (min fresh air requirement).

  3. ACCEPT — In moderate humidity overshoot, allow RH to drift slightly above
     target. The CZ upper bound (80% RH) is the hard limit. Between 60-80% RH,
     the system is still in comfort zone but operating suboptimally.

  Priority order: OA Reduction → Accept (if within CZ) → CC Subcool + Reheat
```

### 10.3 Band Classification

```
FUNCTION classify_oa_band(OA_T, OA_RH):
    OA_W = humidity_ratio(OA_T, OA_RH)
    OA_H = enthalpy(OA_T, OA_W)

    IF OA_T < 5 AND OA_RH < 30:
        RETURN BAND_1_COLD_DRY

    ELSE IF OA_T >= 5 AND OA_T < 15 AND OA_RH >= 30 AND OA_RH <= 60:
        RETURN BAND_2_COLD_MODERATE

    ELSE IF OA_T >= 15 AND OA_T < 20 AND OA_RH < 30:
        RETURN BAND_3_COOL_DRY

    ELSE IF OA_T >= 18 AND OA_T < 22 AND OA_RH >= 30 AND OA_RH <= 50:
        RETURN BAND_4_COMFORT_EDGE_LOW

    ELSE IF OA_T >= 22 AND OA_T <= 25 AND OA_RH >= 40 AND OA_RH <= 60:
        RETURN BAND_5_COMFORT_CORE

    ELSE IF OA_T > 25 AND OA_T <= 27 AND OA_RH >= 50 AND OA_RH <= 70:
        RETURN BAND_6_COMFORT_EDGE_HIGH

    ELSE IF OA_T > 27 AND OA_T <= 32 AND OA_RH > 60 AND OA_RH <= 80:
        RETURN BAND_7_WARM_HUMID

    ELSE IF OA_T > 32 AND OA_T <= 38 AND OA_RH > 70:
        RETURN BAND_8_HOT_HUMID

    ELSE IF OA_T > 35 AND OA_RH < 30:
        RETURN BAND_9_HOT_DRY

    ELSE IF OA_T > 30 AND OA_RH > 85:
        RETURN BAND_10_EXTREME_HUMID

    ELSE:
        // FALLBACK — conditions that fall between band definitions
        // Use enthalpy-based classification
        IF OA_H < 30:
            RETURN BAND_2_COLD_MODERATE     // cold-ish, unclassified humidity
        ELSE IF OA_H < 50:
            RETURN BAND_4_COMFORT_EDGE_LOW  // moderate enthalpy
        ELSE IF OA_H < 65:
            RETURN BAND_6_COMFORT_EDGE_HIGH // warm-ish
        ELSE:
            RETURN BAND_8_HOT_HUMID         // high enthalpy
```

### 10.4 Per-Band Setpoint Strategies

Each band outputs a setpoint tuple consumed by the Layer 2 <!--FROZEN-->PI<!--/FROZEN--> loop:
```
OUTPUT = {
    SA_T_SP,          // Supply air temperature setpoint (deg C)
    SA_W_SP,          // Supply air humidity ratio setpoint (kg/kg)
    OA_DAMPER_SP,     // OA damper position setpoint (%)
    HUM_MODE,         // OFF | HUMIDIFY | SUBCOOL_REHEAT | ACCEPT
    CONTROL_TAG       // Human-readable mode string for dashboard
}
```

```
Dominant load:     Latent dominant + moderate sensible
Control strategy:  RH PRIMARY, T TRIM — CC subcool for dehumidification
Energy profile:    MODERATE delta-H

// Phase 1: Try OA reduction first
RA_W = humidity_ratio(RA_T, RA_RH)
OA_W = humidity_ratio(OA_T, OA_RH)
CZ_W_UPPER = humidity_ratio(25.0, 60)                // target: 60% RH at 25 deg C

IF RA_W < CZ_W_UPPER:
    // Return air is dry enough — reduce OA to dilute moisture
    OA_DAMPER_SP = MIN_OA_POS
    SA_T_SP      = 24.0                               // moderate cooling
    SA_W_SP      = RA_W * 0.85 + OA_W * 0.15          // estimate mixed W at min OA
    HUM_MODE     = ACCEPT
    CONTROL_TAG  = "OA REDUCTION — RA DILUTION"
ELSE:
    // Return air is also humid — must subcool on CC
    OA_DAMPER_SP = MIN_OA_POS
    SA_T_SP      = 12.0                               // subcool below dew point!
    SA_W_SP      = humidity_ratio(12.0, 95)            // approx 8.5 g/kg (saturated at 12 deg C)
    HUM_MODE     = SUBCOOL_REHEAT
    CONTROL_TAG  = "CC SUBCOOL + REHEAT"

    // REHEAT TARGET (what Layer 2 does after subcooling):
    //   CC cools to 12 deg C (moisture condenses on coil)
    //   Then HC reheats to 22-24 deg C
    //   Net result: SA at ~23 deg C / ~40% RH (dehumidified)
    REHEAT_T_SP  = 23.0                               // Layer 2 engages HC after CC

PI Loop Actions (Layer 2):
  IF HUM_MODE = ACCEPT:
    HCV_COOL  -> PI tracks SA_T_SP (moderate)
    HCV_HEAT  -> 0
  IF HUM_MODE = SUBCOOL_REHEAT:
    HCV_COOL  -> PI drives SA_T to 12 deg C first (aggressive — Kp=5.0)
    HCV_HEAT  -> PI reheats to REHEAT_T_SP after CC (Kp=3.0)
    // INTERLOCK: HCV_HEAT only engages when SA_T < 15 deg C (proving subcool worked)
  HUM_VALVE -> 0 (never humidify in this band)
  OA_DAMPER -> MIN_OA_POS

ENERGY WARNING:
  Subcool + reheat is the most expensive operation. The system simultaneously
  cools (to remove moisture) and heats (to restore comfort temperature).
  This should only activate when OA reduction fails. The dashboard should
  ALARM when this mode is sustained for >2 hours — indicates the building
  may benefit from a desiccant dehumidifier retrofit.
```

#### <!--FROZEN-->BAND<!--/FROZEN--> 8: <!--FROZEN-->HOT<!--/FROZEN-->-<!--FROZEN-->HUMID<!--/FROZEN--> (<!--FROZEN-->OA_T<!--/FROZEN--> 32-45 deg C, <!--FROZEN-->OA_RH<!--/FROZEN--> 65-100%)

```
Dominant load:     BOTH sensible and latent — maximum energy demand
Control strategy:  T + RH COMBINED — full mechanical cooling + subcool dehumid
Energy profile:    LARGE delta-H (worst case for energy consumption)

OA_DAMPER_SP     = MIN_OA_POS                        // absolute minimum fresh air
SA_T_SP          = 13.0                              // aggressive subcool
SA_W_SP          = humidity_ratio(13.0, 95)           // approx 9 g/kg at saturation

HUM_MODE         = SUBCOOL_REHEAT
REHEAT_T_SP      = 22.0                              // reheat target after dehumid
CONTROL_TAG      = "MAX COOLING + SUBCOOL DEHUMID"

PI Loop Actions (Layer 2):
  HCV_COOL  -> MAXIMUM EFFORT — PI tracks 13 deg C (Kp=5.0, Ki=1.0)
  HCV_HEAT  -> REHEAT after subcool (PI tracks 22 deg C when SA_T < 15 deg C)
  HUM_VALVE -> 0 (locked off)
  OA_DAMPER -> MIN_OA_POS
  FAN_SPEED -> may increase to compensate for higher pressure drop across wet coil

CRITICAL NOTES:
  1. This is the PEAK ENERGY DEMAND band. Dashboard should show RED alert.
  2. CC is doing double duty: sensible cooling (32 -> 13 deg C = 19 deg C drop!) and
     latent removal (moisture condenses at 13 deg C dew point).
  3. HC then undoes some of the cooling (13 -> 22 deg C reheat) — pure waste from
     an energy perspective, but necessary for comfort without a dehumidifier.
  4. delta-H is maximized. This band represents the strongest argument for
     installing a dedicated dehumidifier or enthalpy wheel.
  5. If CC capacity is insufficient, SA_T may not reach 13 deg C. In that case,
     accept partial dehumidification and raise SA_T_SP to what the coil can
     deliver. Never sacrifice freeze protection.
```

### 10.5 Transition Smoothing

Bands must not cause step-changes in setpoints when <!--FROZEN-->OA<!--/FROZEN--> drifts across boundaries.
Use a weighted blend when <!--FROZEN-->OA<!--/FROZEN--> is within +/-1 deg C or +/-5% <!--FROZEN-->RH<!--/FROZEN--> of a band boundary.

```
FUNCTION smooth_transition(current_band, previous_band, OA_T, OA_RH):

    // Only smooth if band changed this cycle
    IF current_band == previous_band:
        RETURN setpoints_for(current_band)

    // Compute proximity to boundary (0 = on boundary, 1 = deep in new band)
    boundary_dist = min_distance_to_band_boundary(OA_T, OA_RH, previous_band)
    blend = clamp(boundary_dist / BLEND_ZONE, 0, 1)  // BLEND_ZONE = 1.5 deg C or 5% RH

    old_sp = setpoints_for(previous_band)
    new_sp = setpoints_for(current_band)

    RETURN {
        SA_T_SP:      old_sp.SA_T_SP * (1-blend) + new_sp.SA_T_SP * blend,
        SA_W_SP:      old_sp.SA_W_SP * (1-blend) + new_sp.SA_W_SP * blend,
        OA_DAMPER_SP: old_sp.OA_DAMPER * (1-blend) + new_sp.OA_DAMPER * blend,
        HUM_MODE:     blend > 0.5 ? new_sp.HUM_MODE : old_sp.HUM_MODE
    }

MINIMUM DWELL TIME:
    A band must be active for at least 5 minutes before allowing transition.
    Prevents rapid oscillation near band boundaries.
```

### 10.6 Anti-Hunting Logic

```
// Prevent band oscillation when OA conditions hover near a boundary
BAND_CHANGE_LOCKOUT = 300 seconds (5 minutes)
BAND_HYSTERESIS_T   = 1.0 deg C
BAND_HYSTERESIS_RH  = 3.0%

FUNCTION apply_hysteresis(candidate_band, current_band, time_in_current):
    IF candidate_band == current_band:
        RETURN current_band

    IF time_in_current < BAND_CHANGE_LOCKOUT:
        RETURN current_band     // too soon to switch

    // Only switch if OA has moved decisively into the new band
    // (past the hysteresis margin, not just on the edge)
    IF oa_clearly_in_band(candidate_band, BAND_HYSTERESIS_T, BAND_HYSTERESIS_RH):
        RETURN candidate_band
    ELSE:
        RETURN current_band     // stay put
```
